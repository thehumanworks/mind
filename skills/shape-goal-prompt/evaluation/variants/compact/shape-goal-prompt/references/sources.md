# Source notes

Research checked 21 October 2026. The skill's field order, state labels and decision rules are an engineering synthesis. The literature supports their ingredients; it does not establish an optimal universal schema or guarantee agent performance.

| Practice | Primary support | Scope/limit |
| --- | --- | --- |
| Capture purpose, constraints, assumptions and feedback | [NASA 4.1](https://www.nasa.gov/reference/4-1-stakeholder-expectations-definition/) | Institutional systems-engineering guidance; scale formality to the task. |
| Make requirements clear, feasible and verifiable; distinguish needs from means | [NASA Appendix C](https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/) | Preserve user-mandated methods; precision alone does not justify a target. |
| Check intended usefulness as well as specified conformance | [NASA 5.4](https://www.nasa.gov/reference/5-4-product-validation/) | A prompt review cannot validate the later outcome. |
| Separate goals, constraints, preferences and alternatives | [van Lamsweerde, 2001](https://webperso.info.ucl.ac.be/~avl/files/RE01.pdf) | Requirements research, not a modern LLM prompting experiment. |
| Weigh clarification against interruption; allow refinement | [Horvitz, 1999](https://www.microsoft.com/en-us/research/publication/principles-mixed-initiative-user-interfaces/) | Qualitative design principles; no supported universal question quota. |
| Establish sufficient understanding through repair | [Clark and Brennan, 1991](https://web.stanford.edu/~clark/1990s/Clark%2C%20H.H.%20_%20Brennan%2C%20S.E.%20_Grounding%20in%20communication_%201991.pdf) | Human grounding is an analogy, not execution authorization. |
| Recover consequential missing intent before execution | [IN3, ACL 2024](https://aclanthology.org/2024.acl-long.61/) | Includes trained components and simulated interaction; a skill is not that system. |
| Consolidate feedback; remove premature assumptions | [Laban et al., 2025](https://arxiv.org/html/2505.06120v1) | Simulated distributed instructions; historical results do not predict this skill's effect. |
| Define results and constraints without exposed internal reasoning | [OpenAI reasoning guidance](https://developers.openai.com/api/docs/guides/reasoning-best-practices) | Model guidance; avoid copying obsolete API settings. |
| Pair goals with evidence and a blocked stop condition | [OpenAI Goals guide](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex) | The portable prompt does not activate runtime goal features. |
| Use minimal relevant context and proportional scaffolding | [OpenAI skills guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), [Anthropic context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) | Re-evaluate model-specific procedures; necessary context still matters. |
| Constrain deliverables and adapt long-work structure | [Anthropic harness experiments](https://www.anthropic.com/research/harness-design-long-running-apps) | Coding experiments; fixed sprints, subagents and separate evaluators are not universal requirements. |

A better prompt cannot supply missing data, access, judgment or execution infrastructure. Evaluate the actual resulting work as well as the wording.
